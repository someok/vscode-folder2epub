## 简介
本文件系统性阐述"索引文件处理"机制，围绕以下主题展开：
- 索引文件识别规则：文件名匹配逻辑、大小写不敏感处理、特殊命名模式支持（如双下划线前缀、多级子目录索引）。
- 查找策略：直接索引优先、嵌套目录递归搜索、查找范围控制（忽略规则、元数据目录隔离）。
- 导航作用：目录跳转中的 firstFile 选择逻辑、目录目标文件确定、导航结构生成。
- 优先级规则：直接索引优先于其他文件、目录索引优先于子目录索引。
- **新增功能**：可配置 indexName 功能，允许用户自定义索引文件名称（如 'preface' 而非默认的 'index'）。
- 实际场景与配置示例：不同目录结构下的索引识别效果与 EPUB 导航行为验证。

## 详细组件分析

### 索引文件识别规则
- 文件名匹配逻辑
  - 数字前缀解析：仅当"连续数字 + 下划线"出现在文件名开头时，数字部分作为排序序号，其余作为展示名。例如"0000_index.md"会被解析为展示名为"index"，序号为 0。
  - 特殊命名模式：以单个或多个下划线开头的名称（如"__xxx"）被视为展示名为"xxx"，序号为 0。
  - **新增功能**：可配置索引名称识别，使用 isIndexDisplayName(displayName, indexName) 进行判断，支持自定义索引文件名称。
- 大小写不敏感处理：展示名比较采用大小写不敏感策略，确保"Index"、"INDEX"、"index"均被识别为索引。
- 支持的扩展名：仅".md"与".txt"两类文本文件参与索引识别与后续处理。
- 元数据目录隔离：目录名为"__t2e.data"的目录被最高优先级硬过滤，不纳入扫描与索引识别。

### 索引文件查找策略
- 直接索引优先查找：在当前目录的直接子节点中优先寻找标记为索引文件的文件。
- 嵌套目录递归搜索：若当前目录无直接索引，则递归遍历子目录，返回首个找到的索引文件。
- 查找范围控制：
  - 忽略规则：每个目录读取其 .t2eignore 并合并到全局过滤器，过滤掉匹配的相对路径。
  - 元数据目录：即使子目录内存在索引文件，也不会进入结果，因为"__t2e.data"目录被硬过滤。
  - 文件类型限制：仅支持".md"与".txt"。

### 目录跳转中的索引文件作用
- firstFile 选择逻辑：
  - 若当前目录存在索引文件，则 firstFile 指向该索引文件。

- 导航结构生成：在 EPUB 导航中，若某目录存在索引文件，导航项会优先指向该索引文件，且通常不再单独显示该目录项本身（具体以测试断言为准）。

### 标题层级规范化与 stripTopMarkdownHeading 功能

**更新** 新增标题层级规范化处理，确保索引文件内容与父目录标题层次协调

- **stripTopMarkdownHeading 核心功能**：
  - 目标：移除索引文件内容中的最高层级标题，避免与父目录标题产生重复层级
  - 实现：识别内容中第一个非空的标题行，将其移除并清理后续空行
  - 应用场景：当索引文件作为目录入口时，其内容直接附加在父目录标题下，无需重复的顶级标题

- **标题层级处理流程**：
  1. **规范化处理**：将内容中所有标题统一左移到从 # 开始的基础层级
  2. **索引文件特处理**：对索引文件应用 stripTopMarkdownHeading 移除最高层级标题
  3. **层级调整**：根据父目录的章节层级整体下移标题层级，避免与外层标题冲突

- **处理效果**：
  - 索引文件内容不再包含顶级标题，直接作为父目录的子内容展示
  - 避免 EPUB 导航中出现重复的标题层级结构
  - 保持内容的语义完整性，同时优化阅读体验

## 性能考量
- 时间复杂度
  - 扫描阶段对每个目录进行一次 readdir，随后对子目录递归扫描，整体近似 O(N)（N 为有效文件与目录总数）。
  - 索引查找在每个目录最多进行一次直接索引检查与一次子目录递归检查，不影响总体复杂度。
  - **新增开销**：可配置索引名称处理对每个文件的 isIndexDisplayName 调用开销极小，时间复杂度为 O(1)。
  - **新增开销**：stripTopMarkdownHeading 功能对索引文件内容进行一次性处理，时间复杂度为 O(L)，其中 L 为内容行数。
- 空间复杂度
  - 递归深度受目录层级影响，最坏情况下与最大嵌套深度成正比。
  - 结果集包含树状节点与线性文件列表，空间与节点数量线性相关。
  - **新增开销**：标题层级处理需要临时存储内容行数组，空间复杂度为 O(L)。
  - **新增开销**：元数据读取缓存 indexName 配置，内存开销极小。
- 优化建议
  - 合理使用 .t2eignore 控制扫描范围，避免不必要的目录进入扫描。
  - 对于超大目录，建议分层组织并利用索引文件减少导航层级。
  - **性能优化**：stripTopMarkdownHeading 采用流式处理，只在索引文件上应用，避免对普通文件造成额外开销。
  - **性能优化**：indexName 配置在元数据读取时一次性处理，避免重复计算。

## 故障排查指南
- 症状：目录未出现在导航中
  - 可能原因：该目录下无可用文件（空目录不会进入结果），或所有文件被 .t2eignore 过滤。
  - 排查步骤：检查目录内是否存在".md/.txt"文件，确认 .t2eignore 是否误删了目标文件。
- 症状：导航项显示为"index"
  - 可能原因：目录存在索引文件，且导航优先指向该索引文件。
  - 排查步骤：查看目录节点的 indexFile 与 firstFile，确认是否为索引文件导致的跳转。
- 症状：命令无法执行
  - 可能原因：命令未在资源管理器的本地目录中触发。
  - 排查步骤：确认 VS Code 的命令触发上下文，确保选择的是 file 协议的本地目录。
- **新增症状**：自定义索引文件未被识别
  - 可能原因：metadata.yml 中的 indexName 配置错误或格式不正确。
  - 排查步骤：检查 __t2e.data/metadata.yml 中的 indexName 配置，确认格式正确且无拼写错误。
- **新增症状**：原 index 文件被错误识别为索引文件
  - 可能原因：indexName 配置为空字符串或未正确读取。
  - 排查步骤：确认 metadata.yml 中的 indexName 配置已正确设置，或留空以使用默认 'index'。
- **新增症状**：索引文件内容出现重复标题
  - 可能原因：stripTopMarkdownHeading 功能未正确应用或内容格式不符合预期。
  - 排查步骤：检查索引文件的标题格式，确认是否以标准的 Markdown 标题开头，验证内容处理流程。

## 结论
索引文件处理机制通过"数字前缀解析 + 展示名大小写不敏感 + 目录索引优先"的规则，在目录跳转与导航生成中实现了清晰、可控的行为。**新增的可配置 indexName 功能进一步增强了系统的灵活性，允许用户自定义索引文件名称（如 'preface' 而非默认的 'index'），通过 EpubMetadata 接口扩展和元数据读取机制实现。**结合内容扫描逻辑的动态参数传递和测试用例的全面验证，用户可以灵活地组织内容结构并精确控制索引文件的识别规则。**新增的 stripTopMarkdownHeading 功能进一步增强了索引文件的处理能力，通过标题层级规范化确保索引文件内容与父目录标题层次协调一致，避免了重复标题层级的问题。**测试用例进一步验证了在不同目录结构下索引文件的识别与导航表现，确保了功能的稳定性与可预期性。
